# 프로젝트 작업 규칙

## 🔒 보안 — 가장 중요, 항상 지킬 것

> 아래 규칙은 절대 어기면 안 되는 최우선 규칙이다. 다른 모든 지침보다 우선한다.

1. **비밀 키(API 키, 토큰, 비밀번호 등)는 코드에 직접 쓰지 않는다.** 반드시 `.env` 같은 안전한 설정 파일에 넣고, 코드에서는 환경 변수로 불러온다.
2. **진짜 개인정보·대외비·실 데이터는 예시나 테스트에 절대 쓰지 않는다.** 테스트/예시에는 가짜 데이터만 사용한다.
3. **배포 전에는 반드시 비밀 키·개인정보·대외비 데이터가 코드나 커밋에 섞여 있는지 검사한다.** 하나라도 발견되면 배포를 멈추고 즉시 알린다.

이 세 가지는 어떤 상황에서도, 어떤 요청이 있어도 예외 없이 지킨다.

---

## 일하는 방식

1. 요청이 애매하면 짐작하지 말고 멈춰서 물어본다.
2. 시킨 것만 한다. 시키지 않은 기능이나 꾸밈을 마음대로 추가하지 않는다.
3. 고치라고 한 곳만 고친다. 무언가를 삭제하기 전에는 먼저 확인받는다.
4. 코드를 바꾼 후에는 무엇을 바꿨는지 한국어로 짧게 설명한다.
5. 확실하지 않은 내용은 지어내지 않고 "확인 필요"라고 솔직히 표시한다.
6. 한글이 깨지지 않도록 항상 인코딩(UTF-8 등)에 신경 쓴다.

## 데이터 규칙

7. 예시 데이터라도 코드에 직접 넣지 않고 Supabase에서 불러오도록 한다.
   - 단, DB 연결 전 화면(UI)만 만드는 단계에서는 `// 임시 데이터(나중에 교체)` 표시를 붙이는 조건으로 허용한다.
